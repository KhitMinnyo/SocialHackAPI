Upload Document

Calls POST /api/v1/upload/document (multipart form). The filename you send is joined into the server's storage path with no normalization and no extension allow-list, so ../ in the filename escapes the intended uploads/ folder entirely, and any extension - including .py or .svg - is accepted and stored exactly as sent. This page mirrors Chapter 24 (File Upload Attacks & Path Traversal).

A native file picker never lets you type a path into a filename, so this page sends whatever is in the box above instead of the picked file's real name - exactly like editing the multipart body in Burp Suite would.

"View / Open file" calls a second endpoint, GET /api/v1/upload/view?path=..., using the same box - it has the identical unsanitized-path bug on the read side, so it can open a file that escaped uploads/ just as easily as one that never left it. If the SVG example above renders as an image and its script runs when opened, that's the Chapter 24 SVG→stored-XSS chain happening for real; whether it does depends on how this server maps .svg to a content type, so treat it as something to observe rather than something guaranteed.

The traversal, unrestricted-type, and SVG examples really write to disk. python run.py --reset only resets the database, not these files - delete them by hand afterward if you want a clean tree (e.g. INJECTED.txt in the project root, and shell.py / evil.svg under uploads/).
